# PHP engine port design

Date: 2026-07-20
Module: `apps/api/src/Engine/`

Ports the deterministic engine to PHP so the authoritative server computes the
same results as the client. The golden fixtures in
`test-fixtures/engine-cases.json` drive both engines; if a case disagrees, the
game is no longer deterministic across client and server.

## What makes the two agree

**Truncation toward zero, everywhere.** TypeScript's BigInt `/` and PHP's
`intdiv()` both truncate toward zero. `>>` is deliberately not used for signed
division on either side, because it floors on negatives and would diverge. The
`edge-div-trunc-*` fixtures pin this down: `div(-1, 3)` is `-21845`, not
`-21846`.

**Scale 2^16, not the originally specified Q32.32.** Every product stays inside
a native signed 64-bit integer, so PHP needs no ext-gmp and no hi/lo split. The
safe multiply range is about +/-46340 in real units; physics runs in local
metres and stays well inside.

**Lookup tables are copied, not recomputed.** `SineTable.php` and
`DecayTable.php` are generated by `packages/engine/scripts/gen-php-tables.mjs`,
which _reads the committed TypeScript tables_ and re-emits them as PHP rather
than recomputing from the formula. Recomputing would give two sources of truth
that could drift; copying makes them identical by construction.

## Where PHP deliberately differs

TypeScript computes in arbitrary precision and wraps to 64 bits at the end.
PHP has no such wrap: an overflowing int silently becomes a float, which would
diverge quietly and produce wrong game state rather than an error.

So `FixedPoint::mulExact()` guards every multiply and throws `RangeException`
instead. Inside the contractual range the two engines agree exactly; outside
it, PHP fails loudly where TypeScript wraps. Failing loudly is the better
behaviour for an authoritative server, and callers are contractually inside the
range anyway.

`fromString()` similarly refuses more than 18 fractional digits, since 10^19
exceeds `PHP_INT_MAX` and the denominator would become a float.

These are the only intentional behavioural differences, and neither is
reachable from valid gameplay input.

## Fixture coverage

Expanded from 42 to 127 cases. The 85 additions were derived from the
TypeScript engine and target where cross-language ports actually break:

- truncation direction on negative `mul` and `div`
- trig across all four quadrants, plus wrap-around and negative angles
- sine interpolation _between_ table entries, not on 1/16 degree boundaries
- non-perfect-square roots
- exact decimal parsing of negatives and repeating fractions
- `fromParts` with a negative whole part
- decay at awkward millisecond offsets, including mid-interpolation
- level thresholds and the value one XP below each

All 127 pass on both engines.

## Not ported

`Trajectory` is ported but has no fixtures yet: its inputs are structs, and the
fixture encoding is currently scalar-only. The TypeScript side has unit tests
for it. Extending the encoding to cover struct arguments would let
`trajectory.compute` and `blast.resolve` join the shared contract, and is the
obvious next increment.

## Update 2026-07-21: struct arguments

The fixture encoding now handles structs and lists, closing the gap noted
above. Arguments decode recursively (string is a Fixed, number is a plain int,
object is a struct, array is a list), and results are normalised to a tree of
strings before comparison. That one change covers scalars, nested structs and
lists of structs without per-shape special cases.

`trajectory.compute` and `blast.resolve` are now in the shared contract. Both
were ported and unit tested before, but nothing proved the two engines agreed
on them; a vacuum-parabola solver chaining sin, cos, mul and div is exactly
where truncation differences would surface.

Struct fields carrying literal text are listed in `RAW_STRING_FIELDS`
(`weaponId`), mirroring `RAW_STRING_ARGS` one level down. A test in each runner
asserts both tables, so they cannot drift silently.

PHP keeps positional parameters where TypeScript takes an input object, so the
PHP runner destructures rather than the fixture carrying two shapes.
